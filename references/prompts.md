# camiAI 编程全流程提示词库

这些提示词用作可复制的示例。使用时替换产品名称、目录和当前阶段需要的信息；某阶段被用户跳过时，不要继续套用该阶段提示词。命令和文件路径需按当前 Agent 与操作系统调整。

## 1. 初始化项目规则

```text
阅读仓库已有的通用说明和当前 Agent 专属规则，例如 AGENTS.md、CLAUDE.md、GEMINI.md、.cursor/rules/、.github/copilot-instructions.md 或同类文件。不要覆盖已有约定。若项目缺少适合的通用说明，请创建或补充根目录 AGENTS.md，写入下面这些内容，最后提交一个 Git commit：

注意事项
- 每次改动完成后，都必须创建一个对应的 Git commit，以便后续追踪和回滚。
- 每次改动后，都必须编写或更新相关测试，并在交付给用户前，确保所有测试和验证全部通过。
```

新项目先检查当前目录和 Git 状态；已有项目先阅读实际存在的通用说明和 Agent 专属规则，保留已有约定并补充缺少的内容。

## 2. 讨论 MVP 产品方案

```text
我想做一个[产品名称]，打算先从 MVP 版本开始。你觉得这一版做哪些功能比较合适？
```

截图中的原例：

```text
我想做一个电子书阅读器，打算先从 MVP 版本开始。你觉得这一版做哪些功能比较合适？
```

先讨论和确认范围，不要把示例中的产品功能当作新产品的默认需求。

## 3. 制作 Demo

```text
帮我做一个 Demo，不用实现真实的后端功能，数据模拟一下就行。我主要想先看看整体界面和操作流程是否合理。
```

Demo 用于确认界面和操作流程。除非用户另有要求，不连接真实后端或服务。

## 4. 讨论技术栈

```text
这个目录下有一份产品设计文档，请你读一遍这个产品设计文档，然后告诉我，用什么技术栈实现这个产品比较合适。不用给出过于详细的设计，我们先探讨一下。我听说 Electron 还可以，你怎么看？
```

把“产品设计文档”和 Electron 等示例替换成当前项目的实际文件与候选技术。先给出简明比较和建议，留在讨论阶段等待用户决定。

## 5. 撰写技术方案

```text
行，就按你说的来，现在请你写一个技术方案，放在 docs 文件夹里面。
```

只有在用户认可技术方向后，才把方案写入项目的 `docs/`。

## 6. 实现与 AI 自测

```text
请按照已确认的产品范围和技术方案实现本阶段功能。每次改动后编写或更新相关测试，并运行相关测试和验证；修复失败项后再交付。每个完成的改动创建对应 Git commit，并说明实现内容、测试结果和 commit。
```

若用户跳过产品设计或技术设计，使用其已给出的需求与技术选择；缺少关键条件时先提问，不自行补造要求。

## 7. 人工验收

```text
请给我一份简明的人工验收步骤，告诉我如何运行 Demo/产品、逐项检查主要操作流程，以及需要重点留意的问题。我体验后会把问题反馈给你。
```

AI 自测和人工验收是两个阶段：即使 AI 自测通过，也要把人工验收步骤交给用户。

不同 Agent 的 Skill 触发命令各不相同。若本流程没有自动加载，可使用该 Agent 的手动 Skill 调用方式，或请它读取 `SKILL.md` 后按其中流程执行。
